# گزارش ممیزی امنیتی افزونه Karsabt Core

تاریخ: ۱۴۰۵/۰۹/۰۳  
شاخه بررسی: `main`  
شاخه اصلاحات: `security/atomic-otp-mobile-uniqueness`

## دامنه بررسی

ممیزی ایستای فایل اصلی افزونه و ماژول‌های سفارش، مشتری، احراز هویت OTP، مدارک، پیام‌رسانی، امور مالی، گزارش‌ها، داشبورد کارشناس و زمان‌سنج انجام شد. قالب وردپرس کارثبت نیز جداگانه بررسی شد.

## اصلاحات امنیتی این شاخه

1. برای فرم عمومی ثبت سفارش، محدودیت تلاش بر اساس IP اضافه شد: حداکثر ۵ تلاش در بازه ۱۵ دقیقه.
2. پاسخ مسیر ارسال و تأیید OTP یکسان‌سازی شد تا وجود یا نبود حساب کاربری از متن خطا قابل تشخیص نباشد.
3. برای ارسال OTP محدودیت مستقل بر اساس IP اضافه شد: حداکثر ۱۰ درخواست در ساعت.
4. برای بررسی OTP محدودیت مستقل بر اساس IP اضافه شد: حداکثر ۳۰ تلاش در ۱۵ دقیقه.
5. مسیر دریافت مدرک از hook کاربران مهمان حذف شد. دریافت فایل فقط از مسیر کاربر واردشده و پس از بررسی مالکیت سفارش یا مجوز مدیر انجام می‌شود.
6. برای OTP، قفل نام‌گذاری‌شده MySQL روی شماره موبایل اعمال شد تا ارسال هم‌زمان و تأیید هم‌زمان یک کد سریالی شود؛ کد موفق فقط یک بار مصرف می‌شود.
7. شمارنده‌های محدودیت IP و شماره موبایل هنگام خواندن/افزایش با قفل مشترک دیتابیس محافظت می‌شوند؛ در صورت شکست قفل، عملیات OTP با خطا متوقف می‌شود.
8. جدول اختصاصی InnoDB برای نگاشت شماره موبایل به کاربر اضافه شد؛ شماره موبایل و شناسه کاربر هر دو قید یکتا دارند.
9. شماره‌های موبایل موجود از user meta به جدول یکتا مهاجرت می‌شوند و ورود/ثبت‌نام از ایندکس دیتابیس استفاده می‌کند.
10. آزمون واقعی MariaDB برای رقابت دو درخواست تأیید یک OTP اضافه شد؛ فقط یکی از دو درخواست می‌تواند موفق شود.
11. آزمون اجرایی برای قید یکتای موبایل و جلوگیری از اختصاص یک شماره به دو حساب اضافه شد.
12. آزمون‌های ایستای امنیتی مشترک قالب و افزونه همچنان اجرا می‌شوند.

## کنترل‌های امنیتی موجود که در بررسی تأیید شدند

- بررسی nonce در فرم‌های حساس.
- بررسی capability و نقش برای مسیرهای مدیریتی و پرونده‌های کارشناسان.
- محدودیت نوع MIME واقعی و اندازه فایل مدارک.
- ذخیره مدارک در مسیر خصوصی خارج از web root و بررسی مسیر واقعی فایل هنگام دریافت.
- تولید شناسه تصادفی برای فایل‌ها و مدارک.
- استفاده از `$wpdb->prepare()` در پرس‌وجوهای دارای ورودی.
- escape خروجی‌های متنی و HTML در بخش‌های بررسی‌شده.
- محدودیت تعداد تلاش OTP برای هر شماره و زمان انقضای کد.

## موارد باقی‌مانده برای سخت‌سازی بیشتر

1. محدودیت نرخ OTP هنوز از Transient وردپرس به‌عنوان ذخیره شمارنده استفاده می‌کند؛ افزایش آن با قفل دیتابیس سریالی شده و در نصب‌های متکی به پایگاه داده مشترک چندسروری اتمیک است. اگر object cache اختصاصی هر node به‌صورت جداگانه استفاده شود، باید backend مشترک و تنظیم‌شده باشد.
2. پیام‌ها و فهرست مدارک در post meta به‌صورت آرایه نگهداری می‌شوند؛ برای بار هم‌زمان بالا بهتر است به جدول‌های مستقل با عملیات اتمیک منتقل شوند.
3. اتصال‌دهنده پیامک باید از نظر اعتبار پاسخ، timeout، ثبت لاگ بدون ذخیره OTP و مقابله با ارسال انبوه بررسی شود.
4. محدودیت نرخ درخواست پشت reverse proxy باید با تنظیم امن IP واقعی سرور هماهنگ شود؛ به هدرهای قابل جعل مانند `X-Forwarded-For` بدون پیکربندی پراکسی مورد اعتماد تکیه نشود.
5. آزمون نفوذ مستقل و بررسی تنظیمات وب‌سرور/هاست واقعی همچنان انجام نشده است.

## آزمون و محدودیت

این گزارش علاوه بر بررسی کد، شامل آزمون‌های مستقل PHP و آزمون‌های اجرایی وردپرس/MariaDB است. آزمون‌های هم‌زمانی تراکنش، قفل‌ها، مصرف یک‌باره OTP و مسیرهای HTTP واقعی در GitHub Actions اجرا می‌شوند. آزمون نفوذ مستقل و بررسی تنظیمات وب‌سرور/هاست واقعی هنوز انجام نشده است.

هیچ ادعایی درباره امنیت کامل سامانه مطرح نمی‌شود. پیش از انتشار نهایی، نسخه پشتیبان کامل فایل‌ها و دیتابیس تهیه و آزمون بازیابی انجام شود.
