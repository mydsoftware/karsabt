## موانع انتشار

### امنیت و هم‌زمانی

- محدودیت ارسال OTP، cooldown و شمارنده تلاش‌ها با transientهای غیراتمیک پیاده‌سازی شده‌اند؛ درخواست‌های هم‌زمان می‌توانند از محدودیت عبور کنند.
- محدودیت تعداد بارگذاری ساعتی و تعداد مدارک هر سفارش نیز در برابر درخواست‌های هم‌زمان اتمیک نیست.
- برای رفع اصولی، ذخیره‌سازی اتمیک مبتنی بر جدول اختصاصی/قفل یا عملیات SQL اتمیک، همراه با آزمون چنددرخواستی لازم است.
- آزمون فعلی مدارک فقط تابع جست‌وجوی شناسه را پوشش می‌دهد؛ بارگذاری، دانلود، nonce، مالکیت، MIME، حجم، مسیر و فایل‌های orphan هنوز باید در WordPress واقعی آزموده شوند.

### وابستگی‌های عملیاتی

- درگاه پیامک واقعی هنوز متصل و تأیید نشده است؛ فیلتر `karsabt_send_otp` باید از سرویس‌دهنده واقعی پاسخ دقیق `true` دریافت کند.
- مسیر خصوصی فایل باید روی سرور نهایی تعریف، خارج از ریشه وب قرار داده و دسترسی نوشتن آن بررسی شود.
- HTTPS، پشتیبان‌گیری و بازیابی، ایمیل/پیامک عملیاتی و تنظیمات تولید باید روی میزبان نهایی بررسی شوند.
